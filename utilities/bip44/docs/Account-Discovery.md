# BIP 44 第七课：账户发现与地址间隙限制

## 场景

你的手机丢了。你拿出助记词，在一个全新的钱包里恢复。

钱包拿到了种子，能派生出无限多的密钥。但它面临一个问题：

> **你之前用过哪些账户？每个账户用过哪些地址？**

钱包不可能把 `address_index` 从 0 扫到 2³¹，那得扫到天荒地老。

## 账户发现算法

BIP 44 给出的算法非常朴素：

```
1. 从 account = 0 开始
2. 派生这个账户的外部链（change = 0）
3. 扫描外部链上的地址，看有没有交易记录
4. 如果整条外部链没有任何交易 → 停止，发现结束
5. 如果有交易 → account + 1，回到第 1 步
```

就是一个**线性扫描**，遇到空账户就停。

这就是 BIP 44 要求**不允许跳号创建账户**的原因。如果允许跳号：

```
account 0  ✅ 有交易
account 1  ❌ 空的
account 2  ✅ 有交易    ← 扫描到 account 1 就停了，永远发现不了这里
```

## 地址间隙限制（Gap Limit）

账户内部也有同样的问题：钱包怎么知道扫到哪个 index 就够了？

BIP 44 的答案：

> **连续遇到 20 个没用过的地址，就停。**

这就是 **gap limit = 20**。

```
index 0  ✅ 有交易
index 1  ✅ 有交易
index 2  ❌
index 3  ❌
index 4  ✅ 有交易    ← 间隙只有 2，继续扫
index 5  ❌
...
index 24 ❌           ← 连续 20 个空地址，停止
```

## 一个容易踩的坑

假设你一口气预生成了 25 个地址贴在网站上收款，但只有第 25 个收到了钱：

```
index 0~23  ❌ 没交易（连续 24 个空地址）
index 24    ✅ 有交易
```

恢复钱包时，扫到 index 19 就停了——**你的钱"消失"了**。

所以 BIP 44 要求：

> 钱包软件应该在用户即将超过 gap limit 时**发出警告**。

这不是币丢了，只是钱包扫不到。手动调大 gap limit 就能找回来，但这需要用户知道发生了什么。

## 为什么只扫外部链？

注意算法只扫 `change = 0`（外部链），不扫 `change = 1`（内部链）。

原因很简单：**内部链只接收找零，而找零一定来自你自己发起的交易。你发起交易的前提是外部链上有币进来。**

所以——外部链有交易 → 内部链才可能有找零。扫外部链就够了。

## 要点总结

- 账户发现：从 account 0 线性扫描，遇到空账户就停
- 地址间隙限制：连续 20 个空地址就停止扫描
- 这两个机制是"不允许跳号"规则的根本原因
- 只扫外部链，因为内部链的存在依赖外部链
