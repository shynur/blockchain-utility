# 网页版 BIP 44 钱包

## 入口 section

### 助记词输入框 (仅支持英文)

根据输入的单词数量, 自动判断使用了哪种词数的方案.
有了助记词和 passphrase, app 内部就可以生成 master key.

输入时, 校验词数是否为 12/15/18/21/24 之一.
若命中, 则立即执行助记词校验及后续计算;
若继续输入, 则前次结果作废, 并重新校验并生成 master key.

#### 合法字符

- 英文字母
- 空白字符

#### 输入过滤

- 忽略所有 非法字符 的 击键/文本粘贴.

- 输入的文本必须以英文字母开头, 否则
  - 忽略相应的击键
  - 如果是粘贴的文本, 则一直 trim 到首个非空白字符

#### 隐私保护

正在输入单词中, 单词完整显示.
此时, 删除仅删除一个字符.

当输入空白字符时, 表示刚才那个单词已输入完毕, 转为隐藏状态 (i.e., 显示成 `①②③④⑤⑥⑦⑧⑨⑩⑪⑫⑬⑭⑮⑯⑰⑱⑲⑳㉑㉒㉓㉔` 中的一个, 表示第 N 个 word).
同时, 开始输入下一个单词.
单词之间多余的空白字符会被忽略, 仅保留一个空格.

当下一个单词还没字母时, 所有单词都处于隐藏状态.
此时删除一次, 会删除前方的整个单词.

(用户可以在输入全部的助记词之后, 故意追加一个空格, 使得最后一个 word 也隐藏起来.)

### passphrase 输入框

位于 word 输入框之后.

#### 合法字符

- 空格 (` `)
- 其它所有非空白字符

#### 输入过滤

- 忽略所有 非法字符 的 击键/文本粘贴.

#### 隐私保护

每个字符都会显示成 `*`.

### xpub/xprv 输入框

入口除了 word/passphrase 输入框, 还有 xpub/xprv 输入框.
xpub/xprv 输入框复用了 word 输入框.

当 word 输入框检测到已输入的文本以 `xpub`/`xprv` 开头,
则会把输入当成 xpub/xprv 处理, 此时切换到序列化密钥导入模式, 只允许 base58 字符被写入.
同时 passphrase 输入框会被隐藏, 但已输入的 passphrase 会保留以供切换回助记词模式时继续输入.

若用户删除字符导致前缀不再是完整的 `xpub`/`xprv`, 则回退到助记词模式.

#### 长度限制

在 111-char 处显示 `|` 作为视觉标尺, 供用户核对长度.

到达 111 字符时自动触发校验, 并禁止继续输入.

#### 隐私保护

- xpub: 全文明文显示
- xprv: 除了 `xprv` 这个前缀, 后续字符全部显示成 `*`

## 状态 section

导入密钥的元信息:
- level (depth)
- index (若有)
- parent fingerprint (若有)
- identifier

若密钥不通过校验, 显示报错信息.

## `Path 选择` section

对于导入的 xprv/xpub, 它已走过 path 是定死的, 只能选择后续的子节点.
但 app 可以通过 xprv/xpub 获取它的 `depth` 和 `i`,
对于 depth≥1, 已走过的 path 的最后一个节点是可以据 `i` 显示的;
其余节点, 若需推测,
- `purpose'` 节点假设恒为 `44'`
- 其它未知 index 的节点, 根据用户在卡片上的选择显示
并使用 underline 标注.

导入 xpub 时, 由于 xpub 无法进行 hardened 派生,
depth 之后所有需要直接/间接 hardened 派生的 path 卡片会被隐藏.

当导入的是 master xpub 时, 无法继续派生出任何子节点.
此时整个 `生成结果` section 会被隐藏.

### path 预览

`Path 选择` section 上方显示当前完整路径的预览,
如 `m / 44' / coin_type' / account' / change / {address_index}`.

当导入 xpub 时, 使用 xpub 专用的路径标注格式:
- 对于 master key, 使用 `M` 作为 path
- 其余使用 `N(m / 44' / ... / last_level')` 或 `N(m / 44' / ... / account') / change / {address_index}`

路径中的节点处显示的 index 值随用户选择实时更新.

### 节点卡片

卡片有以下特殊状态:
- 不可编辑: 由导入的 xprv/xpub 的 depth 决定, 对应的那个 depth 的 index 是已知的, 因此不需要用户手动编辑
- 不可达: 导入 xpub 时, 后续需要 hardened 派生的层级, 卡片被隐藏
- 选中: 用户点击切换, 选中状态有视觉高亮和边框描边

#### `purpose'`

固定 `44'`.

#### `coin_type'`

包含一个下拉框.

默认 BTC, 按 app 支持情况允许选择其它币种.

#### `account'`

包含一个输入框, 后面有个 `H`.

输入框长度为 1, 根据输入动态变长.

粘贴时, 若文本超出合法范围, 则尽可能多地插入所含数字.

#### `change`

包含一个 switch.
switch 上显示当前值 (`0` 或 `1`).

卡片内容由 switch 切换显示.

#### `address_index`

包含一个输入框, PC 端按回车确认输入, 移动端点击旁边的添加按钮.

合法范围: `[0, 2^31)`, 输入时自动检测范围.
粘贴时, 若文本超出合法范围, 则尽可能多地插入所含数字.

可以输入多个.
列表自动去重, 按从小到大排序.
列表中每个元素后面有个 `❌` 可以移除该元素.

### 生成 xprv/xpub/k/K/A

每张卡片表示 path 中的一个节点, 可以选择是否要在此节点处生成 xprv/xpub.
选项以 checkbox 的形式呈现给用户.

对于 `address_index` 卡片: 它不生成 xprv/xpub, 而是允许选择是否生成 `k` 和 `K`.
当 `coin_type'` 是 BTC 或 BTC testnet 时, `address_index` 额外允许选择是否生成 `A`.

如果 xprv/xpub/k/K/A 中的某一个, 在该节点无法生成, 则干脆不显示该 checkbox.
E.g., 无法派生, 或 导入的是子节点的密钥从而无法推导出父节点的信息.

#### k (私钥)

若该币种有 WIF 版本 (BTC, TBTC, LTC, DOGE, ZEC, BCH), 则以 WIF 格式展示;
否则以 hex 格式展示.

默认隐藏, 后跟一个 button 用来切换 显示/隐藏.

#### K (33-byte 压缩公钥)

以 hex 格式展示.

#### A (address)

Bitcoin P2PKH address.

#### xprv

若无法生成 xprv (e.g. 使用了 xpub 进行导入), 则压根不显示该选项.

默认使用 `xprv***` (此处省略若干个 `*`) 格式隐藏, 后跟一个 button 用来切换 显示/隐藏.

## 报错

出错时, 需要在诱因处用红字显示报错信息以及预期输入或可能的解决方案 (若有).
